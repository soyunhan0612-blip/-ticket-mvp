# UX 원칙

> 스타일 규약(색·컴포넌트·좌석 시각 규칙)은 `UI_GUIDE.md` 참조.

## 디자인 원칙
1. **도구처럼 보인다** — 티켓 서비스는 매일 쓰는 대시보드가 아니라 목적 있는 잠깐의 도구. 마케팅 페이지 톤 금지
2. **좌석 상태는 색 하나로 즉시 구분된다** — available / held-other / held-mine / sold. 4색 이상 쓰지 않는다
3. **정보 밀도가 낮은 화면(공연 목록)과 극단적으로 높은 화면(좌석맵)이 공존한다** — 같은 컴포넌트 룰을 억지로 적용하지 않는다

## UI 원칙 (Figma 7원칙 — 이 프로젝트 해석)

위 3개 원칙이 "무엇을 지킬 것인가"라면, 아래 7원칙은 "왜 지키는가"의 근거다. UI_GUIDE.md의 스타일 규약과 좌석 시각 규칙이 이 원칙에서 파생된다.

### 계층 (Hierarchy)
- 화면당 가장 강한 시각 요소는 **하나뿐**. 목록·상세에서는 "예매하기"/"회차 선택" CTA, 좌석맵에서는 `held-mine` 좌석
- 카드 제목이 페이지 제목보다 진해지거나, 설명 텍스트가 CTA보다 눈에 띄면 계층 실패로 본다
- 폰트 굵기·색·크기 셋 중 하나로 대비를 만든다. 셋을 동시에 밀면 시끄러워진다

### 점진적 공개 (Progressive Disclosure)
- 여정은 목록 → 상세 → 회차 → 좌석의 깔때기다. 각 단계에서 다음 단계에 필요한 최소치만 노출한다
- 좌석맵의 하단 SelectionBar는 좌석을 처음 클릭하기 전까지 **렌더링하지 않는다**. 총액·타이머는 선택이 있어야 의미가 있다
- 셀러 등록 폼은 필드 5개 이내. AI 설명은 "생성" 버튼 이후에만 나타난다 (PRD Day 8 제약과 동일 근거)

### 일관성 (Consistency)
- 재사용 컴포넌트는 카드·버튼·입력 세 종류로 제한. 새 변형을 만들기 전에 기존을 재조합할 수 있는지 먼저 본다
- 색은 `UI_GUIDE.md`의 팔레트 밖으로 나가지 않는다. 좌석맵 4색도 이 규칙의 특례가 아니라 확장
- Admin은 좌석맵 컴포넌트를 **그대로** 재사용한다. 차트 라이브러리 도입은 이 원칙 위반이자 PRD의 "3대 함정" 중 하나

### 대비 (Contrast)
- Primary 액션은 흰색 배경 하나. 부정색은 **파괴 액션에만** 쓴다 (예매 취소, 좌석 반환)
- 좌석맵에서 `available` 과 `sold`의 명도차가 스캔 속도를 결정한다. 이 두 상태의 대비가 흐릿하면 즉시 조정
- 배경 대비 텍스트 4.5:1 미만 조합은 사용하지 않는다 (아래 "접근성 스코프")

### 접근성 (Accessibility)
- 좌석 SVG는 별도 스코프로 분리한다 — 아래 "접근성 스코프" 섹션 참조
- 비좌석 UI(폼·목록·버튼·토스트)는 WCAG AA 대비, `:focus-visible` 포커스 링, `<label htmlFor>` 폼 라벨을 지킨다
- 아이콘만 있는 버튼 금지 — 텍스트 라벨을 함께 둔다 (`aria-label`은 최후 수단)

### 근접성 (Proximity)
- 관련 정보는 하나의 블록으로 묶는다. 좌석 개수 / 총액 / "예매 진행" 버튼은 SelectionBar 한 덩어리
- 회차 선택은 공연 상세 페이지 안에 둔다. 별도 페이지로 뜯지 않는다 — 사용자 머릿속에서는 한 결정
- 서로 다른 성격의 액션(예: "예매하기" 와 "취소")은 물리적으로 떨어뜨린다

### 정렬 (Alignment)
- 좌측 정렬 기본. 중앙 정렬은 빈 상태(empty state)와 로딩 스피너에만 허용
- 좌석맵은 SVG `viewBox` 좌표계가 곧 그리드다. 좌석 위치는 격자에서 벗어나지 않는다
- 카드·폼 필드는 같은 좌측 기준선을 공유. 인덴트로 서열을 표현하지 않는다

## 화면별 원칙 적용

각 화면에서 지켜야 할 것들. 괄호 안은 이 결정의 근거가 되는 원칙.

### 공연 목록 `/shows` (PRD Day 2)
- 카드 그리드 · 정보 밀도 낮음 · 카드 안 계층은 제목 > 회차 요약 > 포스터 순 (계층 / 근접성)
- 빈 상태 카피는 중앙 정렬, 그 외 정렬은 좌측 (정렬)
- 카드 hover 상태는 border 색 변화만. glow·scale 금지 (일관성 / 안티패턴)

### 공연 상세 `/shows/[id]` (PRD Day 2)
- 포스터 · 설명 · 회차 리스트를 한 페이지에 (근접성)
- 셀러 설명은 `whitespace-pre-wrap` plain text. 마크다운 렌더 금지 (일관성 / 접근성)
- 회차 리스트에서 매진된 회차는 명도만 낮춰 표시. 취소선·배지 남발 금지 (대비)

### 좌석 선택 `/sessions/[id]/seats` (PRD Day 3~6)
- 4상태 색만 사용. `held-mine`이 페이지에서 가장 강한 시각 요소 (계층 / 대비)
- 초기 `viewBox`는 무대 앞 중앙부. 전체 보기는 명시적 버튼으로만 (점진적 공개)
- SelectionBar는 최초 선택 이전에 렌더되지 않는다. 총액·타이머·"예매 진행"은 하나의 덩어리 (점진적 공개 / 근접성)
- 서버 폴링 결과로 좌석이 회색화될 때 애니메이션 없이 즉시 반영. 사용자가 "왜 안 눌리지"를 겪지 않도록 (대비)

### 예매 확정 · 내역 · 취소 `/reservations` (PRD Day 7)
- 취소는 부정색 텍스트 버튼. Primary와 물리적으로 분리 (대비 / 근접성)
- 내역 목록은 좌석 상세를 접힘 상태로 두고 클릭 시 확장 (점진적 공개)
- 성공·실패 토스트는 동일한 컴포넌트, 색만 다르게 (일관성)

### 셀러 등록 `/seller/new` (PRD Day 8)
- 필드 5개 이내. 좌석 배치는 프리셋 3개 카드 중 선택 (점진적 공개)
- AI 설명은 "생성" 이후 스트리밍 프리뷰 박스에 plain text로 표시. 저장 전 편집 가능 (일관성 / 접근성)
- 폼 라벨은 `<label htmlFor>`로 명시. placeholder만으로 라벨 대체 금지 (접근성)

### Admin `/admin` (PRD Day 9)
- 좌석맵 컴포넌트를 그대로 재사용. 차트 라이브러리 금지 (일관성 · PRD "3대 함정")
- 숫자 카드 4개는 동일 카드 컴포넌트 재사용. 배지·아이콘 최소화 (일관성)
- 숫자 하나가 다른 것보다 압도적으로 커지면 계층 실패. 4개는 대등 (계층)

## 접근성 스코프

MVP에서 무엇을 포함하고 무엇을 미루는지 명시한다. "몰라서 안 한 것"과 "알고 미룬 것"의 구분.

### MVP 포함 — 비좌석 UI 전반
- 텍스트·배경 대비 WCAG AA (본문 4.5:1, 큰 텍스트 3:1)
- 모든 인터랙티브 요소에 `:focus-visible` 링. 마우스 사용자에겐 보이지 않고 키보드 사용자에게만 노출
- 폼: `<label htmlFor>` 로 라벨-필드 연결. placeholder는 힌트일 뿐 라벨이 아니다
- 버튼: 텍스트 라벨 필수. 아이콘 단독 버튼 금지 (`aria-label` 은 최후 수단)
- 토스트: `role="status"` (성공/정보) 또는 `role="alert"` (에러)
- 문서 언어: `<html lang="ko">`

### MVP 제외 — 좌석 SVG 키보드 · 스크린리더
- 좌석맵의 키보드 내비게이션 (arrow key로 좌석 이동, Enter로 선택) 및 스크린리더 라벨링은 MVP에서 뺀다
- 사유: 2000석 SVG에서 제대로 하려면 별도 설계가 필요하다. 대충 넣으면 "접근성 있음"이 아니라 "접근성 있는 척"이 된다 (PRD "MVP 제외 사항" 참조)
- README에 이 결정과 사유를 명시한다. 알고 뺀 것이라는 서사

### AI 생성 텍스트 (셀러 설명)
- `dangerouslySetInnerHTML` 금지. plain text + `whitespace-pre-wrap` 만 사용
- 이 규칙은 XSS 방어이자 스크린리더 파싱의 최소 조건 — 두 요구가 같은 곳에서 만난다 (CLAUDE.md CRITICAL 규칙과 동일)
- AI에게 마크다운 없이 문단만 쓰도록 프롬프트에서 지시
