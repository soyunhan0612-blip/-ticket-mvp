# Step 4: metrics-writeback

## 읽어야 할 파일

먼저 아래 파일들을 읽고 프로젝트의 아키텍처와 설계 의도를 파악하라:

- `/docs/ADR.md` — 특히 ADR-002. **이 step에서 적는 문장이 ADR-002의 입장과 모순되면 안 된다**
- `/docs/PROGRESS.md` — Day 3 절(94~104줄), Day 4 절(106~139줄) 전체
- `/README.md` — "성능 before / after" 절(52~61줄)과 Day 상태 표(37~48줄)
- `/docs/PERF_MEASUREMENT.md` — **step 3에서 생성됨**
- `/src/components/seat/__tests__/naive-render-count.test.tsx` — **step 1에서 생성됨.** 실제 측정값의 출처
- `/src/components/seat/__tests__/seat-render-count.test.tsx` — **step 2에서 생성됨.** 실제 측정값의 출처
- `/src/atoms/seat.ts` — `seatVisualStateAtomFamily`의 의존 구조 (52~76줄)
- `/phases/11-perf-metrics/index.json` — step 1·2의 `summary`에 기록된 측정 수치

## 배경

step 1·2가 리렌더 수치를 테스트로 고정했고, step 3이 수동 측정 절차를 문서화했다.
이 step은 그 결과를 `docs/PROGRESS.md`와 `README.md`의 빈칸에 반영한다.

`10-release/step2`가 blocked된 사유는 "필수 실측값이 모두 없음"이었다.
이 step 이후 리렌더 관련 값은 근거를 갖추게 되고, 남는 것은 브라우저가 필요한
**초기 마운트 시간**뿐이다. 그 항목은 공란으로 남기되, 어떻게 채우는지 `PERF_MEASUREMENT.md`를
가리키게 한다.

### 반드시 반영해야 할 서사 결정

이 프로젝트는 "추정값은 기록하지 않는다", "과장하지 않는다"를 명시적 기조로 삼는다.
따라서 **React 리렌더 수와 파생 atom 재계산 수를 나란히 병기**한다.

근거: `src/atoms/seat.ts:52-76`의 `seatVisualStateAtomFamily`는 read 함수에서
`selectedSeatIdsAtom`을 통째로 구독한다. 좌석 하나를 클릭하면 모든 좌석의 파생 atom이
재계산되고, 반환값이 같으면 Jotai가 컴포넌트 리렌더만 건너뛴다.
즉 `atomFamily` + `memo`가 없애는 것은 **React 리렌더**이지 **atom 재계산**이 아니다.
이 사실을 숨기면 코드를 읽는 심사자가 발견했을 때 서사의 허점이 되므로 정면으로 적는다.

## 작업

### 1. 측정값 확보

`phases/11-perf-metrics/index.json`의 step 1·2 `summary`에서 실제 측정 수치를 읽는다.
값이 불명확하면 해당 테스트를 직접 실행해 확인하라:

```bash
npm test -- src/components/seat/__tests__
```

**추정하지 마라.** 테스트가 출력한 값만 쓴다.

### 2. `README.md` 성능 표 갱신 (52~61줄)

현재:

```markdown
| 측정 | Day 3 (before) | Day 4 (after) |
|---|---|---|
| 좌석 1회 클릭 시 리렌더 컴포넌트 수 | TBD | TBD |
| 초기 마운트 시간 | TBD | TBD |
```

갱신 방향:

- 리렌더 행: 실측값으로 치환. **측정 좌석 수를 함께 밝혀라** (예: 200석 기준). 2,000석 값은 비례 관계로 따라 나온다는 점을 각주로 적어라
- **파생 atom 재계산 행을 새로 추가**
- 초기 마운트 시간 행: `TBD` 유지하되, `docs/PERF_MEASUREMENT.md`를 가리키는 링크를 달아 "왜 비어 있는지"와 "어떻게 채우는지"를 명확히 하라
- 표 아래 문단에 **"`atomFamily`가 없애는 것은 React 리렌더이지 atom 재계산이 아니다"**는 각주를 추가하라. 기존 문단(61줄)의 "초기 마운트 비용은 개선되지 않는다"는 서술은 유지한다 — 둘은 다른 이야기이고 둘 다 맞다
- 자동 측정 항목은 `npm test`로 재현 가능하다는 점과 테스트 파일 경로를 명시하라

### 3. `docs/PROGRESS.md` 갱신

**Day 3 "before 측정" 절 (94~100줄)**

- 97줄 `- 초기 마운트 시간: **_ ms` → 수동 측정 대기임을 명시하고 `PERF_MEASUREMENT.md` 참조
- 98줄 `- 좌석 1회 클릭 시 리렌더 컴포넌트 수: **_` → 실측값 + 출처 테스트 파일 경로
- 측정 근거가 `91713d0` 커밋의 재현 픽스처라는 점을 밝혀라 (`src/components/seat/__fixtures__/naive-seat-map.tsx`)

**Day 4 "after 측정" 절 (129~135줄)**

- 132줄 `- 초기 마운트 시간: **_ ms** (Day 3: **_ ms**)` → 수동 측정 대기 + 참조
- 133줄 `- 좌석 1회 클릭 시 리렌더 컴포넌트 수: **_** (Day 3: **_**)` → 실측값 + 출처
- **파생 atom 재계산 횟수 항목을 새로 추가**하고, 위 "서사 결정"의 근거를 1~2문장으로 적어라

**주의**: 97·98줄은 `**_ ms` / `**_`(볼드 미닫힘), 132·133줄은 `**_ ms**` / `**_**` 형태로
표기가 통일돼 있지 않다. 두 패턴 모두 처리하라. 132·133줄은 한 줄에 플레이스홀더가
2개씩 있어 실제 빈칸은 총 6개다.

**Day 3/Day 4 절 제목**

현재 Day 4 절 제목은 `## Day 4 — 좌석 최적화 after (구현 완료, 측정 대기)`다.
리렌더 측정이 완료됐으므로 "측정 대기"의 범위가 좁아졌다. 제목을 실제 상태에 맞게 조정하라
(예: 초기 마운트 시간만 대기 중임이 드러나게). Day 3 절도 동일하게 검토하라.

### 4. `README.md` Day 상태 표 갱신 (37~48줄)

42·43줄의 `구현 완료·측정 대기`가 현재 상태와 맞지 않게 된다.
리렌더는 측정 완료, 초기 마운트 시간만 대기임이 드러나게 문구를 조정하라.

### 5. 문서 간 정합성 확인

같은 수치가 `README.md`, `docs/PROGRESS.md` 두 곳에 나온다. **서로 어긋나면 안 된다.**
또한 `docs/ADR.md`의 ADR-002가 "클릭당 리렌더 2000 → 1~2"라고 적고 있다면,
실측값과 다를 경우 ADR을 실측에 맞게 수정하지 말고 **각주로 실측 조건을 병기**하라.
ADR은 결정 기록이므로 사후에 숫자만 바꿔 쓰면 기록의 성격이 훼손된다.

## Acceptance Criteria

```bash
npm run lint
npm test
```

추가 확인:
- `docs/PROGRESS.md`에 `**_` 패턴이 남아 있지 않은지 검색해 확인하라
- `README.md`의 리렌더 관련 `TBD`가 남아 있지 않은지 확인하라 (초기 마운트 시간의 `TBD`는 의도적으로 남김)

## 검증 절차

1. 위 AC 커맨드를 실행한다.
2. 아키텍처 체크리스트를 확인한다:
   - 문서만 수정했고 `src/` 프로덕션 코드는 무수정인가?
   - 적은 수치가 전부 테스트 실측값인가? 추정한 숫자가 하나도 없는가?
   - `README.md`와 `docs/PROGRESS.md`의 같은 수치가 일치하는가?
   - ADR-002의 결정 기록을 사후 조작하지 않았는가?
3. 결과에 따라 `phases/11-perf-metrics/index.json`의 해당 step을 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약"`
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "…"`
   - 사용자 개입 필요 → `"status": "blocked"`, `"blocked_reason": "…"` 후 즉시 중단

**초기 마운트 시간이 비어 있다는 이유로 이 step을 blocked 처리하지 마라.**
그 항목은 브라우저가 필요한 수동 측정이며, 절차가 `docs/PERF_MEASUREMENT.md`에 문서화된
상태로 남기는 것이 이 phase의 설계된 종료 조건이다.

## 금지사항

- 초기 마운트 시간을 추정해서 적지 마라. 이유: 이 프로젝트는 "추정값은 기록하지 않는다"를 README에 명시했다. 근거 없는 숫자 하나가 문서 전체의 신뢰를 깎는다.
- 파생 atom 재계산 층을 생략하지 마라. 이유: 코드를 읽는 심사자가 `seatVisualStateAtomFamily`의 `selectedSeatIdsAtom` 의존을 발견하면 "2000 → 1~2"만 적힌 문서는 과장으로 읽힌다.
- ADR-002의 본문 숫자를 실측에 맞춰 덮어쓰지 마라. 이유: ADR은 시점의 결정 기록이다. 실측과 다르면 각주로 병기한다.
- `src/` 아래 프로덕션 코드를 수정하지 마라. 이유: 이 step은 문서 레이어만 다룬다.
- 측정 조건(좌석 수, 폴링 배제 여부)을 생략한 채 숫자만 적지 마라. 이유: 조건 없는 수치는 재현 불가능하고, 재현 불가능한 수치는 추정과 구분되지 않는다.
- 기존 테스트를 깨뜨리지 마라.
